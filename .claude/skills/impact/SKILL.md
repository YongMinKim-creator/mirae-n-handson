# 변경 영향도 분석

## 원칙
- **읽기만 한다.** 코드 · 스키마 · 문서를 고치지 않고 파일도 만들지 않는다. 결과는 답변으로만 낸다.
- 코드에서 확인한 것만 적는다. 모든 항목에 근거 `파일:줄번호` 를 붙이고, 줄번호를 댈 수 없으면 "추적 한계"로 보낸다.
- **호출 방향을 뒤집지 않는다.** "A → B" 는 A 의 본문에서 B 를 부르는 줄을 인용할 수 있을 때만 쓴다. include · import · 주입만 있고 호출이 없으면 "참조"로 적는다.
- **존재하지 않는 함수 · 파일 · 테이블 · 컬럼을 쓰지 않는다.** 이름을 적기 전에 Grep 으로 정의 위치를 찾는다.
- 근거 표기: 저장소 루트 기준 경로(`legacy/item-bank-php/search.php:215`, `db/mariadb/init/01-schema.sql:70`).

## 0. 인자 해석
- `$ARGUMENTS` 는 이름(`distribute`, `buildSearchQuery`, `usp_calc_grade`) 또는 `파일:줄번호` 다.
- `파일:줄번호` 면 그 줄을 포함하는 함수 · 메서드 · 프로시저를 대상으로 삼는다.
- 이름이 여러 곳에 정의돼 있으면(오버로드 · 같은 이름의 다른 클래스 · 다른 모듈) 후보를 `파일:줄` 로 나열하고 **멈춰서 묻는다.**
- 인자가 없거나 정의를 찾지 못하면 멈추고 묻는다.
- 대상이 속한 모듈명은 경로로 정한다: `legacy/item-bank-php` → `item-bank`, `legacy/assignment-thymeleaf` → `assignment`, `legacy/grade-mssql` → `grade`, `modern/**` → 패키지 도메인(`com.example.item` → `item`).

## 절차

### 1. 정의 위치
- 대상의 정의 `파일:줄`(시작 ~ 끝), 시그니처, 한 줄 요약을 적는다.

### 2. 호출부 역추적
- 직접 호출부를 모두 찾는다. 검색 패턴 예:
  - PHP: `이름(`, `->이름(`, `::이름(`
  - Java: `.이름(`, 메서드 참조 `::이름`
  - SQL: `EXEC 이름`, `EXECUTE 이름`, 다른 프로시저 본문 · 코드의 문자열 `"이름"`
- 각 호출부가 속한 함수를 다시 대상으로 삼아 같은 검색을 반복한다. **진입점에 닿으면 그 경로는 끝낸다.** 진입점:
  - PHP: URL 로 직접 열리는 최상위 파일(`search.php` 의 최상위 코드)
  - Spring: `@GetMapping` · `@PostMapping` · `@RequestMapping` 메서드, `@Scheduled`, `@EventListener`
  - 템플릿 · 폼: `th:action`, `<form action=...>`, 링크 `href` — 화면 → URL 연결 근거로 적는다
  - MSSQL: 애플리케이션 코드가 부르는 프로시저, SQL Agent 작업 정의가 저장소에 있으면 그것
  - modern/web: 컴포넌트 → `hooks/use*` → `api/items.ts` → 엔드포인트
- 같은 함수를 여러 번 방문하면 한 번만 적고 순환은 "순환"으로 표시한다.
- 테스트 코드(`src/test/**`, `*.test.tsx`, `characterization/**`)의 호출은 경로에 넣지 않고 6단계 "기존 테스트"로 따로 모은다.

### 3. 테이블
- 대상 함수 본문과 그 함수가 부르는 DAO · 쿼리 함수에서 SQL 을 찾아 테이블별로 읽기(SELECT) · 쓰기(INSERT · UPDATE · DELETE)를 `파일:줄` 로 적는다.
- 스키마(`db/mariadb/init/`, `db/mssql/init/`)에서 그 테이블의 정의 · FK · 뷰 · 트리거를 찾는다. 뷰 · 트리거가 그 테이블을 쓰면 함께 적는다.
- 같은 테이블을 쓰는 **다른** 함수를 저장소 전체(legacy · modern)에서 찾는다. 대상이 **쓰는** 테이블이면 그 테이블을 읽는 곳이 우선이다(대상 변경으로 결과가 달라지는 쪽).

### 4. 관련 규칙
- `docs/<모듈명>/BUSINESS-RULES.md` 가 있으면 규칙 중 근거 `파일:줄` 이 1~3단계에서 찾은 함수 · 줄 범위에 들어가는 것을 규칙 ID 로 연결한다.
- 파일이 없으면 "BUSINESS-RULES.md 없음"이라고 적고, 규칙을 새로 만들지 않는다.
- 규칙 문서의 줄번호가 현재 코드와 다르면(인용 코드가 그 줄에 없으면) "문서 줄번호 불일치"로 적는다.

### 5. 추적 한계
- 아래가 보이면 검색으로 호출부를 다 찾았다고 할 수 없다. 해당 `파일:줄` 과 이유를 "추적 한계"에 적는다.
  - PHP: 가변 함수 `$fn(`, `call_user_func`, `include $var`, 문자열로 만든 메서드 이름
  - Java: 리플렉션(`Method.invoke`, `Class.forName`), 인터페이스 · 상속을 통한 호출(구현체가 여럿), Spring 프록시 · AOP · 이벤트, 템플릿 표현식 안의 메서드 호출
  - SQL: 동적 SQL(`EXEC(@sql)`, `sp_executesql`), 트리거, 문자열로 조립한 테이블 · 컬럼 이름
  - 저장소 밖 호출자(배치 · 외부 시스템 · 운영 DB 작업)

### 6. 테스트 케이스 제안
- 수정 **전에** 현재 동작을 고정할 테스트를 제안한다. 각 제안에 입력 · 기대 결과 · 근거 `파일:줄` · 관련 규칙 ID 를 붙인다.
- 우선순위: ① 대상 함수의 분기 · 경계(조건문마다 참/거짓 1개) ② 진입점별 정상 경로 1개 ③ 대상이 쓰는 테이블을 읽는 다른 화면의 결과 ④ 오류 · 예외 경로.
- 이미 있는 테스트(`src/test/**`, `*.test.tsx`, `characterization/` 스냅샷)가 덮는 것은 "기존 테스트: `파일:줄`" 로 표시하고 새로 제안하지 않는다.

## 출력 형식

~~~markdown
# 영향도: <대상 이름> (`파일:줄`)

## 1. 영향받는 화면
| 화면 · URL | 진입점 `파일:줄` | 경로 번호 |

## 2. 호출 경로
- P1: `진입점 파일:줄` → `파일:줄` → … → **대상** `파일:줄`
  (각 화살표는 호출하는 줄의 `파일:줄`)

## 3. 영향받는 테이블
| 테이블 | 대상의 읽기/쓰기 `파일:줄` | 스키마 `파일:줄` | 같은 테이블을 쓰는 다른 함수 `파일:줄` (읽기/쓰기) |

## 4. 관련 규칙 ID
| 규칙 ID | 근거 `파일:줄` | 연결 이유 |

## 5. 수정 전에 확보할 테스트
| # | 입력 · 상황 | 기대 결과 | 근거 `파일:줄` | 규칙 ID | 기존 테스트 |

## 6. 추적 한계
| 위치 `파일:줄` | 이유 |
~~~
- 해당 항목이 없으면 표를 비우지 말고 "없음(확인한 검색: …)"이라고 적는다.

## 하지 말 것
- 코드 · 스키마 · 문서 · 스냅샷을 고치지 않는다. 수정 방법을 제안하지 않는다(요청이 영향 범위일 때).
- 검색 결과가 없다는 이유만으로 "영향 없음"이라고 단정하지 않는다. 5단계 추적 한계를 확인한 뒤에만 쓴다.
- 이름이 비슷한 다른 함수(`findById` 가 여러 DAO 에 있는 경우 등)를 대상의 호출부로 섞지 않는다. 호출 대상의 타입 · 변수를 확인한다.
- 적기 전에 인용한 `파일:줄` 이 실제 그 줄과 같은지 다시 읽어 확인한다.
