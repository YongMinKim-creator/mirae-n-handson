# RCA 리포트 마스킹 규칙

리포트를 저장하기 전에 아래 규칙을 본문 · 표 · 발췌 · 명령 출력 전체에 적용한다.
리포트 파일을 처음 쓸 때부터 마스킹한 값으로 쓰고, 저장 후 한 번 더 검색해 남은 값이 없는지 확인한다.

| 대상 | 규칙 | 예 |
|---|---|---|
| IP 주소 | 구분이 필요하면 역할 별칭으로 바꾼다. 구분이 필요 없으면 `x.x.x.x` | `API-1`, `API-2`, `교사단말A`, `교사단말B` |
| 이메일 | `***@도메인` 형태로 로컬 파트를 가린다. 도메인도 개인 식별 가능하면 `***@***` | `***@example.com` |
| 학생 식별자 | `STU-…` 형태에서 번호를 지우고 `STU-…` 로 쓴다 | `STU-…` |
| 토큰 (Bearer · API 키 · 세션 ID · JWT) | 값 전체를 `[TOKEN]` 으로 바꾼다. 앞 몇 글자도 남기지 않는다 | `Authorization: Bearer [TOKEN]` |
| 비밀번호 · 접속 문자열 | 비밀번호 값을 `[PASSWORD]` 로 바꾼다. 접속 문자열은 계정과 비밀번호를 가린다 | `jdbc:mariadb://host/db?user=[USER]&password=[PASSWORD]` |

## IP 역할 별칭

- 같은 IP 는 리포트 전체에서 같은 별칭으로 쓴다. 다른 IP 는 다른 별칭으로 쓴다.
- 서버 쪽은 `API-1`, `API-2`, `DB-1`, `NGINX-1` 처럼 역할 + 번호로, 사용자 단말은 `교사단말A`, `학생단말A` 처럼 역할 + 알파벳으로 쓴다.
- 별칭은 로그 안의 역할(User-Agent · Referer · 접근 경로 · 호스트명)로 정한다. 역할을 알 수 없으면 `클라이언트A` 로 쓴다.
- IP 에서 파생한 값(역방향 DNS 이름, 서브넷 · 마지막 옥텟)도 같이 가린다.

## 적용 방법

- 별칭과 원래 값의 대응표를 파일로 만들지 않는다. 대응은 작업 중 기억 안에서만 쓰고, 답변에도 원래 값을 적지 않는다.
- 마스킹 전 원본 리포트를 임시 폴더나 다른 파일에 복사해 두지 않는다. 원본 로그는 수정하지 않는다.
- 명령 예시에 원본 값이 들어갈 때는 `<교사단말A 의 IP>` 처럼 별칭 자리표시자로 쓴다.
- 파일:줄번호 · 시각 · 건수 같은 분석 근거는 가리지 않는다.
- 리포트 마지막 줄에 적용 결과를 한 줄로 적는다. 건수만 쓰고 값은 쓰지 않는다.
  예: `마스킹 적용: IP 14건(4종 → 교사단말A~D) · 이메일 0건 · 학생 식별자 0건 · 토큰 0건 · 비밀번호/접속 문자열 0건`
